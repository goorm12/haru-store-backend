# 커밋 메시지 컨벤션 (Commit Convention)

- **문서 버전:** v0.1
- **대상:** `haru-store-backend`
- **목적:** 일관되고 가독성 높은 커밋 이력을 유지하여 코드 리뷰 및 변경점 추적을 용이하게 한다.

---

## 1. 커밋 메시지 기본 구조

커밋 메시지는 **제목(Title)**과 **본문(Body)**으로 구성하며, 제목과 본문 사이에는 반드시 **빈 줄 한 줄**을 둡니다.

```text
<Type> : <제목> #<이슈번호>

- <상세 작업 내용 1>
- <상세 작업 내용 2>
```

---

## 2. 제목 규칙

```text
<Type> : <제목> #<이슈번호>
```

1. **`<Type>`**: 작업의 성격을 나타내는 태그 (아래 타입 목록 참조)
2. **` : `**: 타입 뒤에 **공백 + 콜론 + 공백**을 붙입니다.
3. **`<제목>`**: 어떤 작업을 수행했는지 한눈에 알 수 있도록 명확하고 간결하게 한글로 작성합니다. (마침표는 찍지 않습니다)
4. **`#<이슈번호>`**: 제목 끝에 연관된 GitHub Issue 번호를 붙입니다.

### 📌 커밋 타입 (Type) 목록

| Type | 설명 | 사용 예시 |
| :--- | :--- | :--- |
| **`feat`** | 새로운 기능 추가 | `feat : 회원 가입 및 카카오 로그인 연동 #5` |
| **`fix`** | 버그 수정 | `fix : 예약 취소 시 재고 반환 누락 버그 수정 #8` |
| **`docs`** | 문서 추가 및 수정 | `docs : 기술 스택 명세서 및 ERD 추가 #4` |
| **`style`** | 코드 포맷팅, 세미콜론 누락 등 (코드 로직 변경 없음) | `style : 구글 자바 스타일 가이드 포맷팅 적용 #4` |
| **`refactor`** | 기능 추가나 버그 수정이 없는 코드 리팩터링 | `refactor : 예약 검증 로직 Service에서 Domain으로 이동 #8` |
| **`test`** | 테스트 코드 추가, 테스트 리팩터링 | `test : 예약 동시성 100건 요청 테스트 추가 #8` |
| **`chore`** | 빌드 설정 변경, 패키지 매니저 관리, 의존성 라이브러리 추가 등 | `chore : PostgreSQL 드라이버 및 Spring Data JPA 의존성 추가 #4` |

---

## 3. 본문 규칙

```text
- <상세 작업 내용>
```

1. 제목 아래 **빈 줄 한 줄**을 두고 작성합니다.
2. 해당 커밋에서 실제로 변경/구현한 핵심 내용을 **`- ` (불릿 포인트)**로 명확하게 정리합니다.
3. 해당 이슈의 체크리스트(`할 일`) 작업 내역을 반영하여 작성합니다.

---

## 4. 커밋 메시지 예시

### 예시 1) 새로운 기능 추가 (`feat`)
```text
feat : 회원 가입 및 카카오 로그인 연동 #5

- 카카오 OAuth2 토큰 검증 로직 구현
- 회원 식별 후 JWT Access/Refresh 토큰 발급
- 최초 가입 시 필수 약관 및 연락처 형식 검증 처리
```

### 예시 2) 빌드 및 환경 설정 (`chore`)
```text
chore : PostgreSQL 드라이버 및 Spring Data JPA 의존성 추가 #4

- build.gradle에 org.postgresql:postgresql 의존성 추가
- application.yml에 local PostgreSQL 접속 프로파일 구성
```

### 예시 3) 버그 수정 (`fix`)
```text
fix : 픽업 시작일 경과 후 취소 차단 로직 수정 #8

- 픽업 시작일 당일 00:00부터 구매자 직접 취소 시 CustomException 발생하도록 조건식 수정
- 판매자 취소 요청(RSV-06) 유도 안내 메시지 반환
```
