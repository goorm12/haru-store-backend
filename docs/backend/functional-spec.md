# 하루상점 — 백엔드 기능명세서

- 작성일: 2026-10-20 / v0.1
- 대상: haru-store-backend
- 목적: 구매자(buyer)·판매자 및 플랫폼 관리자(management)가 이용할 기능과 서버의 처리 조건을 정의한다.
- 기준: [문서 안내](../README.md)에 연결된 공통 요구사항·용어·역할별 기능명세서.

## 1. 서비스 범위

MVP는 공구 상품 예약 후 상점에서 현장 결제·픽업하는 서비스다. 구매자·판매자는 같은 카카오 회원을 사용하고, 한 판매자가 여러 상점을 운영할 수 있다. 온라인 결제·배송·환불·정산 등은 후속 범위다.

이 문서는 기능의 이용 주체, 입력 정보, 처리 조건, 결과, 예외, 확인 기준을 정리한다. 기존 정책에서 구현 기본안·후속 설계로 남긴 항목은 그대로 구분한다.

## 3. 기능별 상세

### AUTH-01 카카오 로그인·가입

- **이용 주체:** 구매자·판매자
- **입력·시작 조건:** 카카오 로그인 결과, 최초 동의, 이름·연락처
- **처리 규칙:** 같은 카카오 계정은 구매자·판매자 화면에서 같은 회원으로 이용한다. 신규 회원은 필수 정보와 동의를 입력하고, 기존 회원은 누락된 필수 정보만 보완한다. 연락처는 직접 입력하며 형식만 확인한다.
- **처리 결과:** 로그인한 회원과 이용 가능한 역할을 확인할 수 있다. 상점 등록 전에도 구매자로 이용할 수 있다.
- **제한·예외:** 로그인 취소·실패 시 가입이나 예약이 완료되지 않는다. 연락처 소유 인증을 완료한 것으로 표시하지 않는다.
- **확인 기준:** 같은 계정으로 앱·웹에 로그인해도 회원이 중복 생성되지 않는다.

### AUTH-02 회원 정보 수정·로그아웃

- **이용 주체:** 로그인 회원
- **입력·시작 조건:** 이름·연락처 변경 내용 또는 로그아웃 선택
- **처리 규칙:** 본인 정보만 수정할 수 있다. 변경된 정보는 이후 예약에 적용하고 기존 예약 당시 정보는 유지한다. 로그아웃한 기기의 회원 연결과 푸시 연결을 종료한다.
- **처리 결과:** 수정된 본인 정보가 표시되거나 로그아웃 상태가 된다.
- **제한·예외:** 로그아웃·로그인 만료 후 개인정보를 조회하거나 거래를 변경할 수 없다.
- **확인 기준:** 다른 회원으로 로그인했을 때 이전 회원의 예약·알림이 보이지 않는다.

### STORE-01 상점 검색·상세 조회

- **이용 주체:** 비회원·회원
- **입력·시작 조건:** 상점명 검색 또는 상점 선택
- **처리 규칙:** 상점명·주소·소개·연락처·픽업 운영시간을 확인한다. 일반 검색에는 정상 상점을 노출하는 기본안을 따른다.
- **처리 결과:** 검색 결과와 선택 상점 정보를 확인할 수 있다.
- **제한·예외:** 검색 결과 없음과 조회 실패를 구분한다. 제한된 상점의 기존 예약자는 예약에서 당시 픽업 안내를 확인할 수 있다.
- **확인 기준:** 제한된 상점에 신규 예약은 할 수 없지만 기존 예약 안내는 유지된다.

### STORE-02 내 상점 저장·기본 상점 지정

- **이용 주체:** 구매자
- **입력·시작 조건:** 상점 저장·해제 또는 기본 지정
- **처리 규칙:** 같은 상점을 중복 저장하지 않는다. 저장한 정상 상점 중 기본 상점은 최대 하나다. 기본 상점은 구매자가 직접 지정하고 다른 상점 구경만으로 바꾸지 않는다.
- **처리 결과:** 저장 상점 목록과 기본 상점을 확인할 수 있다.
- **제한·예외:** 기본 상점을 해제하거나 이용할 수 없게 되면 지정을 해제하고 재선택을 안내한다. 다른 상점을 임의로 지정하지 않는다.
- **확인 기준:** 기본 상점은 최대 하나이며 저장 해제·제한 시 재선택이 필요하다.

### STORE-03/04 운영 상점 등록·설정·전환

- **이용 주체:** 판매자 또는 상점을 개설하려는 회원
- **입력·시작 조건:** 상점명·픽업 주소·연락처·운영시간, 관리할 상점 선택
- **처리 규칙:** 필수 정보 입력 후 사전 승인 없이 개설한다. 최초 개설 성공 시 판매자 역할을 부여한다. 한 판매자가 여러 상점을 운영하고 본인 소유 상점만 관리한다.
- **처리 결과:** 등록한 상점의 운영 정보를 확인·수정하고 상점별로 전환할 수 있다.
- **제한·예외:** 상점 설정 변경으로 기존 예약의 픽업 약속을 덮어쓰지 않는다. 다른 판매자의 상점을 관리할 수 없다.
- **확인 기준:** 두 상점의 상품·수량·예약 명단이 섞이지 않는다.

### LIST-01 공구 상품 목록·상세 조회

- **이용 주체:** 비회원·구매자·해당 상점 판매자
- **입력·시작 조건:** 상점·공구 선택, 판매자 상태별 조회
- **처리 규칙:** 구매자는 공개 상품의 이미지·설명·단가·판매 단위·접수 상태·한도·예약 마감·픽업 조건·취소 정책을 확인한다. 판매자는 본인 상점의 작성 중 상품까지 확인한다.
- **처리 결과:** 구매자는 예약 가능 여부와 정책, 판매자는 공구 운영 현황을 확인할 수 있다.
- **제한·예외:** 작성 중·예약 예정·접수 중단·숨김·공구 취소·상점 제한·마감·품절이면 신규 예약을 막는다. 기존 예약이 있으면 해당 예약으로 안내한다.
- **확인 기준:** 일반 구매자에게 작성 중 상품이나 다른 구매자의 예약 명단을 노출하지 않는다.

### LIST-02/03 공구 상품 등록·수정

- **이용 주체:** 해당 상점 판매자
- **입력·시작 조건:** 상품명·이미지·설명·단위·단가·수량·한도·접수 일정·픽업일·취소 제한
- **처리 규칙:** 작성 중 저장과 공개를 구분한다. 공개 시 필수 정보와 유효한 일정·수량을 확인한다. 당일 접수 마감은 공구별로 지정한다. 총 수량은 이미 확보된 수량보다 작게 줄일 수 없다.
- **처리 결과:** 작성 중 또는 공개된 공구가 저장되고 변경 내역을 확인할 수 있다.
- **제한·예외:** 가격·직접 취소 정책 변경은 기존 예약에 소급하지 않는다. 예약된 날짜·장소·운영시간은 기존 약속을 유지하거나 별도 안내·처리를 거친다. 실제 상품 구성이 달라지는 변경은 새 공구 등록으로 안내하는 기본안을 따른다.
- **확인 기준:** 기존 단가 10,000원 예약은 공구 가격을 12,000원으로 바꿔도 기존 단가를 유지한다.

### LIST-04/05 접수 중단·재개·공구 전체 취소

- **이용 주체:** 해당 상점 판매자
- **입력·시작 조건:** 처리할 공구, 중단·재개·취소 선택, 취소 사유
- **처리 규칙:** 중단·마감은 신규 예약·수량 증가를 막고 기존 예약은 유지한다. 재개는 유효한 접수 조건에서만 가능하다. 전체 취소는 사유를 입력하고 아직 픽업하지 않은 예약 확정 건을 판매자 취소로 처리한다.
- **처리 결과:** 접수 상태가 변경되거나 대상 예약이 취소되고 수량이 반환되며 구매자에게 안내된다.
- **제한·예외:** 판매자가 관리자 숨김·상점 제한을 해제할 수 없다. 픽업 완료·미수령·이미 취소된 예약을 다시 취소하지 않는다.
- **확인 기준:** 전체 취소를 반복해도 수량을 중복 반환하지 않고 완료 이력을 유지한다.

### RSV-01/02 예약 생성·내 예약 조회

- **이용 주체:** 구매자
- **입력·시작 조건:** 공구, 수량, 픽업일
- **처리 규칙:** 로그인 후 접수 조건·픽업일·남은 수량·개인 한도를 확인하고 판매자 승인 없이 즉시 확정한다. 같은 구매자는 같은 공구에 유효 예약 하나만 유지하며 추가 구매는 수량 변경으로 처리한다.
- **처리 결과:** 예약번호·상품·수량·예약 당시 단가와 예상 금액·픽업일·장소·운영시간·취소 정책을 확인한다. 본인의 예정·지난 예약을 조회할 수 있다.
- **제한·예외:** 동시 예약도 총 수량을 넘지 않는다. 반복 클릭·통신 재시도로 중복 예약하지 않는다. 취소 후 조건 내 새 예약은 가능하지만 픽업 완료 후 같은 공구 재구매는 불가하다.
- **확인 기준:** 잔여 1개에 두 구매자가 동시에 예약해도 한 건만 확정된다.

### RSV-03 예약 수량 변경

- **이용 주체:** 예약한 구매자
- **입력·시작 조건:** 본인 예약, 변경할 수량
- **처리 규칙:** 기존 픽업일 전날까지 변경한다. 증가는 접수가 열려 있고 잔여 수량·개인 한도를 만족해야 한다. 감소는 직접 취소 제한이 없는 예약에서 최소 1개까지 가능하다.
- **처리 결과:** 기존 단가로 수량·예상 금액이 변경되고 증가분은 확보, 감소분은 반환된다.
- **제한·예외:** 당일 변경은 불가하다. 직접 취소 제한이면 감소를 막는다. 실패 시 기존 예약을 유지한다.
- **확인 기준:** 공구 가격 변경 후 수량을 바꿔도 예약 당시 단가를 적용한다.

### RSV-04 픽업일 변경

- **이용 주체:** 예약한 구매자
- **입력·시작 조건:** 본인 예약, 새 픽업일
- **처리 규칙:** 기존 날짜와 새 날짜가 모두 미래이고 공구가 유지하는 유효 픽업일일 때 변경한다. 접수 중단·마감 후에도 변경 기한 내이면 가능하다.
- **처리 결과:** 픽업일·안내가 변경되고 총 확보 수량은 유지된다.
- **제한·예외:** 당일 날짜로 바꾸거나 기존 픽업일 당일에 변경할 수 없다. 공구 취소·종료 예약은 변경할 수 없다.
- **확인 기준:** 접수 중단 후에도 전날까지 유효한 미래 픽업일로 변경할 수 있다.

### RSV-05/06 구매자 예약 취소·처리 요청

- **이용 주체:** 예약한 구매자
- **입력·시작 조건:** 본인 예약, 취소 선택 또는 처리 요청 내용
- **처리 규칙:** 직접 취소 제한이 없고 기존 픽업일 전날까지면 전체 취소한다. 당일 또는 직접 취소가 제한된 경우 상점 문의·법정 요청 등 별도 처리 경로를 제공한다.
- **처리 결과:** 허용 취소는 예약 취소·수량 반환·알림으로 이어진다. 처리 요청은 접수 결과를 안내한다.
- **제한·예외:** 처리 요청 접수만으로 예약을 취소하지 않는다. 취소 복구 대신 새 예약을 이용한다.
- **확인 기준:** 취소 요청을 반복해도 수량은 한 번만 반환된다.

### SELL-01/02 판매자 예약 조회·개별 취소

- **이용 주체:** 해당 상점 판매자
- **입력·시작 조건:** 상점, 픽업일·상품·상태·예약번호·예약자 검색, 취소 사유
- **처리 규칙:** 본인 상점의 예약 목록·상세·오늘 픽업 건수·상품별 준비 수량·경과 예약을 확인한다. 예약 확정 건은 사유를 입력해 개별 취소할 수 있으며 당일에도 관리자 승인 없이 즉시 처리한다.
- **처리 결과:** 대상 예약만 취소되고 수량 반환·구매자 알림·처리 이력이 남는다.
- **제한·예외:** 취소·픽업 완료·미수령 예약은 개별 취소 대상이 아니다. 다른 상점 예약은 조회·처리할 수 없다.
- **확인 기준:** 특정 예약 취소가 다른 예약의 상태·수량에 영향을 주지 않는다.

### SELL-03~06 현장 결제·픽업·미수령·오기록 정정

- **이용 주체:** 해당 상점 판매자
- **입력·시작 조건:** 예약번호 또는 예약자 확인, 현장 처리 선택, 정정 사유
- **처리 규칙:** 현장 결제를 기록하고 상품 전달 후 픽업 완료로 처리한다. 픽업일이 지나면 경과 표시만 하고 판매자가 확인 후 미수령 처리한다. 잘못된 픽업·결제 기록은 각각 사유를 남겨 정정한다.
- **처리 결과:** 예약 상태와 결제 기록을 별도로 확인하고 처리자·시각·정정 전후 내용을 확인할 수 있다.
- **제한·예외:** 날짜 경과로 자동 취소·미수령 처리하지 않는다. 픽업·미수령은 수량을 반환하지 않는다. 결제 기록 정정은 실제 환불·재결제가 아니다.
- **확인 기준:** 픽업·결제 중 하나를 정정해도 다른 기록이 임의 변경되지 않는다.

### NOTICE-B01/S01 상점 공지·댓글·답글

- **이용 주체:** 비회원·구매자·해당 상점 판매자
- **입력·시작 조건:** 상점 공지 내용, 구매자 댓글, 판매자 답글
- **처리 규칙:** 판매자는 공구와 별개로 공지를 작성한다. 공개 공지는 비회원도 읽고 로그인 구매자는 댓글을 작성한다. 판매자는 답글을 작성한다. 각 작성자는 본인 글을 수정·삭제할 수 있다.
- **처리 결과:** 상점 공지와 공개 댓글·답글을 확인한다. 새 공지는 해당 상점을 저장한 구매자 전체에게 안내한다.
- **제한·예외:** 공지 댓글은 예약으로 인정하지 않는다. 판매자가 구매자 댓글을 대신 수정·삭제할 수 없다. 답변이 있어도 본인 글의 수정·삭제를 막지 않는다.
- **확인 기준:** 기본 상점 여부와 관계없이 해당 상점을 저장한 구매자만 새 공지 알림 대상이다.

### INQUIRY-B01/S01 비공개 상점 문의·답변

- **이용 주체:** 문의 작성 구매자·해당 상점 판매자
- **입력·시작 조건:** 상점, 문의 내용, 선택적 공구·본인 예약 연결, 후속 질문·답변
- **처리 규칙:** 문의 작성자와 해당 판매자만 목록·내용·대화를 조회한다. 각자 본인 글·메시지를 수정·삭제한다. 예약 연결은 본인 예약이면서 같은 상점인 경우만 허용한다.
- **처리 결과:** 새 문의·구매자 후속 메시지는 판매자에게, 판매자 답변은 작성자에게 안내한다.
- **제한·예외:** 다른 구매자·판매자·플랫폼 관리자에게 비공개 본문을 노출하지 않는다. 문의 작성·답변만으로 예약 상태·수량·픽업일이 바뀌지 않는다.
- **확인 기준:** 다른 회원이 문의를 직접 찾아도 본문·답변을 볼 수 없다.

### NOTI-01~03, COMM-NOTI-B01 예약·픽업·공지·문의 알림

- **이용 주체:** 알림 수신 회원
- **입력·시작 조건:** 예약·게시물 처리 결과, 픽업일·운영 시작 시각, 알림 설정
- **처리 규칙:** 예약 확정·변경·취소·공구 취소를 안내한다. 픽업은 전날 18시와 당일 시작 2시간 전에 안내하며, 당일 계산이 8시 이전이면 8시로 조정하고 시작 시각 이상이면 생략한다.
- **처리 결과:** 본인 알림 내역과 읽음 상태를 확인한다. 푸시 권한이 없어도 알림 내역을 조회할 수 있다.
- **제한·예외:** 지난 안내는 소급하지 않는다. 날짜 변경·취소·완료·미수령·탈퇴 시 부적절한 예정 알림을 보내지 않는다. 동일 목적 알림을 중복 생성하지 않는다.
- **확인 기준:** 10시 시작은 당일 8시, 9시 시작도 8시, 8시 시작은 당일 사전 알림을 생략한다.

### OPS-01~03 신고·플랫폼 운영 조치·거래 요청

- **이용 주체:** 신고·요청 회원, 별도 권한을 가진 플랫폼 관리자
- **입력·시작 조건:** 상점·공구 신고 또는 거래 요청, 관리자 조치·사유
- **처리 규칙:** 관리자는 신고·요청을 검토하고 사유와 이력을 남겨 상품 숨김·상점 제한·해제를 처리한다. 일반 회원 가입이나 상점 개설로 관리자 권한을 얻을 수 없다.
- **처리 결과:** 처리 결과와 조치 내역을 확인한다. 제한된 상점·숨김 상품은 신규 접수가 차단된다.
- **제한·예외:** 신고 접수나 거래 요청 완료는 자동 예약 취소가 아니다. 기존 예약·문의 경로를 유지한다. 관리자에게 일반 비공개 상점 문의 열람 권한을 부여하지 않는다.
- **확인 기준:** 판매자 취소는 관리자 승인 대기 없이 처리되고 운영 조치는 기존 예약을 자동 취소하지 않는다.

### ACCOUNT-01 회원 탈퇴·미완료 거래 처리

- **이용 주체:** 구매자·판매자
- **입력·시작 조건:** 탈퇴 요청, 미완료 예약·운영 상점 확인
- **처리 규칙:** 미완료 거래와 처리 경로를 안내하고 계정 접근·푸시 연결을 종료한다. 판매자 탈퇴 시 소유 상점의 신규 예약을 중단한다. 불필요한 회원 정보는 정리하고 필요한 최소 거래 기록만 정해진 근거·기간에 따라 분리 관리한다.
- **처리 결과:** 탈퇴 결과와 남은 거래의 처리·문의 경로를 안내한다.
- **제한·예외:** 미완료 거래 때문에 요청을 무기한 거절하거나 기존 예약을 임의 삭제하지 않는다. 모든 정보를 일괄 장기 보관하지 않는다.
- **확인 기준:** 탈퇴 후 다른 회원이 같은 기기에 로그인해도 이전 회원의 예약·푸시 정보가 노출되지 않는다.

## 4. 공통 처리 기준

- 날짜·마감은 한국 시간 기준이다. 전날 23:59:59까지 허용하고 당일 00:00부터 구매자 변경·직접 취소를 막는다.
- 개인정보·거래 정보는 본인 정보·예약 또는 본인 소유 상점 범위에서 접근한다. 공개 조회와 별도 관리자 권한의 신고·운영 조치는 각 기능의 허용 범위를 따른다. 화면에서 다른 회원·상점을 선택해도 권한을 얻지 못한다.
- 예상 금액은 예약 당시 원화 정수 단가×수량이다. 가격·예약자·취소 정책·픽업 약속은 예약 당시 기준을 보존한다.
- 남은 수량은 총 수량에서 예약 확정·픽업 완료·미수령 수량을 뺀 값이다. 개인 한도 미설정도 전체 잔여 수량 제한은 적용한다.
- 준비 수량은 해당 픽업일의 예약 확정 수량 합계다. 수량 감소·취소만 그에 맞는 수량을 반환하고 날짜 변경은 전체 점유를 바꾸지 않는다.
- 공구 접수 상태와 숨김·상점 제한을 구분한다. 품절·픽업일 경과는 별도 예약 상태로 만들지 않는다.
- 실패한 변경은 기존 거래를 유지하며 반복 클릭·재시도로 중복 거래·알림·수량 반환이 발생하지 않는다.
- 알림 발송 실패가 정상 확정된 예약의 실패로 표시되지 않는다.

## 5. 기존 구현 기본안·후속 확인 사항

- 최초 상점 저장 시 기본 상점을 자동 지정하지 않고 구매자가 직접 선택하는 기본안.
- 삭제된 댓글에 다른 사람의 답글이 있으면 원문 삭제 표시를 남기는 기본안.
- 공지 수정·삭제에는 새 공지 전체 알림을 다시 보내지 않는 기본안.
- 예약 있는 날짜·장소 변경의 안내·동의·재선택 흐름.
- 미수령 이후 재예약·늦은 수령·정정의 세부 처리. 미수령 수량은 개인 한도에서 제외하지 않는다.
- 픽업 완료 전에 결제 확인을 필수로 할지에 대한 세부 조건.
- 공지 첨부·상단 고정·댓글 개별 알림·문의 상태 표시 및 판매자 알림 전달 방식.
- 탈퇴 후 미완료 거래 문의·본인 확인과 개인정보 항목별 보관·파기 기준.

후속 확인 사항은 확정된 예약·취소 정책을 변경한다는 의미가 아니다. 구체 조건이 정해지면 해당 기능의 처리 규칙과 확인 기준에 반영한다.
